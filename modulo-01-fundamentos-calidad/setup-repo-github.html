Crear el repositorio

Elige un nombre real de proyecto (no "proyecto-calidad" — algo que podrías defender en una entrevista: gestor-tareas, motor-inventario, lo que sea que vayas a construir durante el curso). Créalo público, para que la evaluación por progreso de repo sea auditable.

bash
# reemplaza NOMBRE-PROYECTO por el nombre real que elegiste
mkdir NOMBRE-PROYECTO && cd NOMBRE-PROYECTO
git init -b main
echo "# NOMBRE-PROYECTO" > README.md
git add README.md
git commit -m "chore: primer commit"

gh repo create TU-USUARIO/NOMBRE-PROYECTO --public --source=. --remote=origin --push

Verifica que quedó publicado visitando https://github.com/TU-USUARIO/NOMBRE-PROYECTO.

.editorconfig — la calidad más barata que existe

Antes de pensar en linters (Módulo 6), elimina la categoría de discusión más tonta en un code review: espacios vs. tabs, o un archivo con final de línea distinto al del resto. Un .editorconfig lo resuelve para cualquier editor que lo respete (VS Code, CLion, PyCharm, Vim con plugin).

.editorconfig
root = true

[*]
charset = utf-8
end_of_line = lf
insert_final_newline = true
trim_trailing_whitespace = true
indent_style = space
indent_size = 4

[*.{yml,yaml,json}]
indent_size = 2

[*.md]
trim_trailing_whitespace = false

Autoevaluación

Pregunta 1 de 5

¿Por qué el repo del curso debe crearse como público en vez de privado?

Correcto: este curso te evalúa por el historial real de tu repo (CLAUDE.md), no por exámenes. Un repo público permite que ese progreso sea verificable en cualquier momento.
Pregunta 2 de 5

¿Qué logra activar Require a pull request before merging en la protección de la rama main?

Correcto: obliga a que todo cambio pase por un Pull Request, incluso los tuyos — es la regla que hace el resto del flujo (Módulo 2) obligatorio por herramienta, no por disciplina personal.
Pregunta 3 de 5

Require status checks to pass before merging queda activado pero vacío (sin ningún check todavía) hasta que llegues a:

Correcto: los status checks los llenan los pipelines de GitHub Actions, que recién construyes en el Módulo 5. Activar la regla desde ya significa que en cuanto tengas CI, será obligatoria automáticamente.
Pregunta 4 de 5

¿Cuál es el propósito principal de un archivo .editorconfig?

Correcto: es la forma más barata de calidad — resuelve algo que ningún revisor debería tener que comentar nunca. El análisis estático "de verdad" (linters, code smells) llega en el Módulo 6.
Pregunta 5 de 5

Un Issue con label de deuda técnica, documentando una decisión tomada a propósito, es parte de la rúbrica de este módulo porque:

Correcto: como viste en la página anterior (deuda técnica), el problema nunca es tomar deuda a propósito — es no dejar registro de que existe. El Issue es ese registro.
