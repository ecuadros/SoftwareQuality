Prerequisitos

  • Cuenta de GitHub personal (no de organización) — este repo lo posees tú.
  • git instalado y configurado (git config --global user.name/user.email).
  • Recomendado: GitHub CLI (gh) instalado y autenticado con gh auth login — lo vas a usar todo el curso.
  • Decide desde ya si tu proyecto será en Python, en C++, o en ambos en paralelo (recomendado para aprovechar todos los labs del curso).
// paso 1

Crear el repositorio

Elige un nombre real de proyecto (no "proyecto-calidad" — algo que podrías defender en una entrevista: gestor-tareas, motor-inventario, lo que sea que vayas a construir durante el curso). Créalo público, para que la evaluación por progreso de repo sea auditable.

bash
# reemplaza NOMBRE-PROYECTO por el nombre real que elegiste
mkdir NOMBRE-PROYECTO && cd NOMBRE-PROYECTO
git init -b main
echo "# NOMBRE-PROYECTO" > README.md
git add README.md
git commit -m "chore: primer commit"

gh repo create TU-USUARIO/NOMBRE-PROYECTO --public --source=. --remote=origin --push

Verifica que quedó publicado visitando https://github.com/TU-USUARIO/NOMBRE-PROYECTO.

Proteger la rama principal

.editorconfig — la calidad más barata que existe

Antes de pensar en linters (Módulo 6), elimina la categoría de discusión más tonta en un code review: espacios vs. tabs, o un archivo con final de línea distinto al del resto. Un .editorconfig lo resuelve para cualquier editor que lo respete (VS Code, CLion, PyCharm, Vim con plugin).

.editorconfig
root = true

[*]
charset = utf-8
end_of_line = lf
insert_final_newline = true
trim_trailing_whitespace = true
indent_style = space
indent_size = 4

[*.{yml,yaml,json}]
indent_size = 2

[*.md]
trim_trailing_whitespace = false
